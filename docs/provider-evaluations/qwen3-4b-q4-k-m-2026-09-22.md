# Qwen3-4B Q4_K_M on llama.cpp Metal — 2026-09-22

## Decision

Adopt this as the initial **quality-default** provider for the gateway. It is
not a claim of JeV model parity. It is the first candidate that provides a
useful quality baseline while fitting comfortably enough on the 16 GB M5 Air.

## Pinned profile

- MacBook Air M5, 16 GB unified memory; macOS 27.0 arm64
- `llama.cpp` 0.4.1, build `b29c606e2`
- Official `Qwen/Qwen3-4B-GGUF`, `Qwen3-4B-Q4_K_M.gguf`
- Context: 8192; all layers offloaded to Metal
- Model file: 2.3 GB; warm `llama-server` RSS: about 3.9 GB

## Gateway-path BBQ-100 result

The benchmark called `POST /v1/systemone` on the local gateway, not
llama.cpp directly. Each Choice question uses a deterministic grammar limited
to its A–Z labels and one generated token. Structured JeV state and
instructions are serialized by the gateway.

## Template caveat

With Qwen3's current chat template, passing `enable_thinking: false` adds an
empty `<think>...</think>` wrapper before the constrained answer. The gateway
does not expose it: it deterministically reads the final grammar-limited
option label. This behavior is covered by the live smoke test and must remain
part of any llama.cpp upgrade check.

## Probability caveat

The provider returns a greedy constrained choice, not token logprobs. Gateway
probabilities are therefore one-hot and `confidence: 1` means only that the
grammar produced a valid label. It is not calibrated model confidence.
