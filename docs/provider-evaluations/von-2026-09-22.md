# Von MPS evaluation — 2026-09-22

## Decision

Do **not** add Von as a quality fallback provider. Its latency is attractive, but
it does not improve the ambiguous, contextual decisions that a small ANE model
cannot safely own. The default Qwen-class local decoder remains the intended
quality provider for the first gateway release.

## Reproducible environment

- MacBook Air M5, 16 GB unified memory
- macOS 27.0, arm64
- Python 3.12.14 in an isolated virtual environment
- Von source revision `2656a69`; PyTorch 2.14.0; Transformers 5.17.0
- `von serve --backend von-1.0 --device mps`

The model downloaded approximately 1.1 GB of Hugging Face cache. The warm
server process showed about 1.05 GB RSS. Cold start and model loading are not
included in the latency figures.

## Contract finding

Von exposes `POST /v1/systemone`, but is not a direct JeV schema substitute:
`choice.instructions` must be a string. JeV callers can send a structured
object (for example, `{ passage, question }`). A compatibility gateway must
normalize structured instructions before calling it.

The smoke test accepted 26 choice IDs and returned normalized probabilities,
but API acceptance must not be confused with decision quality.

## BBQ-100 result

`scripts/evaluate-von-bbq.mjs` converts each structured JeV question into:

- state: a fixed evidence-only policy plus the passage
- instructions: `Question: ...`
- criteria: the original answer strings, retaining their choice IDs

This is deliberately a gateway-style normalization, not a raw Von request.

| Backend | Overall | Ambiguous (50) | Disambiguated (50) | p50 | p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `von-1.0` on MPS | 63% | 50% | 76% | 55.5 ms | 61.9 ms |
| `option-marker` on MPS | 49% | 60% | 38% | 46.0 ms | 66.8 ms |

The normal backend is the only plausible one. Its 50% result on the ambiguous
half is exactly the wrong failure mode for a confidence/uncertainty fallback;
it amounts to chance-level handling of the cases that require a quality model.
The option-marker backend is faster but is unsuitable for this role.

## How to rerun

Start Von separately, then run the harness with a BBQ-compatible JSONL file:

```bash
BBQ_DATA=/path/to/bbq-100.jsonl \
JEV_EVAL_URL=http://127.0.0.1:9021/v1/systemone \
PROVIDER_NAME=von-1.0 \
node scripts/evaluate-von-bbq.mjs
```

The script writes a JSON report to standard output and progress to standard
error. Do not route by an LLM's self-reported confidence; route mechanically,
and only promote a provider after it improves the task slice it is meant to
serve.
